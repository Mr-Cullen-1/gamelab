**Редакция документа:** 1.2 (GameLab) для бета-генерации; `contractVersion` остаётся `1`

**Назначение:** правила разработки и генерации игр для каталога GameLab в ученической LMS Junior.

Название продукта — GameLab (прежнее название — GameCenter). Технические идентификаторы (`// @junior-gamecenter v1`, `gameCenterManifest`, примерные `gameId` и префиксы `gc-…`) намеренно не изменены ради совместимости.

- Приложение B — справочный HTML `GameLab.html`.

Этот документ задаёт целевой контракт GameLab. Названия props, callbacks и форматы ниже — требования к новой интеграции, а не описание уже работающего API. Существующий загрузчик Math Trainer не поддерживает этот контракт автоматически. Для публикации необходим совместимый GameLab runtime; до его появления игру можно проверять в локальном хосте с теми же props.

**Старт для авторов:** по этой редакции можно генерировать бета-файлы JSX/JSON и проверять их с тестовым хостом. Готовность к публикации подтверждается отдельно после подключения настоящего GameLab. Передавайте генератору весь документ, включая бета-профиль, схемы callbacks и промпт. Один скопированный пример не является полной игрой.

## 1. Продуктовые границы

GameLab — каталог бесплатных познавательных игр в ученической LMS Junior. Игры связаны с курсами (с одним или несколькими) только на уровне каталога: каталог рекомендует ученику игры из курсов, на которые он записан, и позволяет фильтровать игры по курсу. Курсы каталога: Matematika, Ingliz tili, Dasturlash, Robototexnika, Raqamli ko‘nikmalar, Mantiq. Игра не является уроком: обязательного прохождения урока, изменения прогресса курса, оценок и наград нет. Сам JSX сведений о курсах не получает; новых props для этого нет. Математика и логика — основные, но не единственные направления.

Допустимы разные механики:

| Тип | Примеры | Граница попытки | Результат |
| --- | --- | --- | --- |
| `level` | Строительство мостов, головоломки | Отдельное испытание уровня | Успех или поражение, показатели уровня |
| `endless` | Змейка, прыжки вверх, бесконечный раннер | Одна партия до проигрыша или выхода | Очки, дистанция, время, рекорд |
| `free` | Конструктор, свободный эксперимент | Значимое действие или работа, определённые автором | Созданный объект, выполненное действие, показатели |
| `mixed` | Игра с уровнями и бесконечным режимом | Определяется выбранным режимом | Показатели соответствующего режима |

Уровни, звёзды, победа и прохождение всей игры необязательны. Нельзя искусственно превращать бесконечную игру в набор уровней или считать проигрыш технической ошибкой.

Обязательны мобильное управление, понятная инструкция перед началом и возможность выйти. Поддержка ПК желательна и явно заявляется автором. Игра работает без звука; важная информация передаётся также визуально. Отключение интенсивных анимаций рекомендуется, но зависит от механики.

Все игровые тексты доступны на узбекском, русском и английском. `lang` платформы определяет текущий язык. Автор отвечает за инструкции, переводы, механику, проверку решений, подсчёт показателей, звуки и визуальные эффекты.

Платформа отвечает за каталог, запуск, привязку данных к ученику, хранение попыток и прогресса, версии и доставку результатов. Отображение статуса сохранения внутри игры обеспечивает JSX.

Монеты, учебные награды, обязательное прохождение урока и ежедневные ограничения в контракт не входят. Ручное исправление, удаление и сброс результатов через админку отложены за первую production-версию. Управление версиями и публикацией игр остаётся частью платформы.

## 2. Что передаёт автор

1. Один UTF-8 файл `Game.jsx` с полной игровой логикой и интерфейсом.
2. Необязательный UTF-8 файл `Game.json` с контентом: уровнями, вопросами, ответами, заданиями или настройками.
3. Обложку и сведения для карточки: название, рекомендуемые классы (`gradeFrom`–`gradeTo`, 1–11; на карточке показывается как «3–4-sinf»), развиваемый навык, необходимые начальные знания, а также курсы каталога (`courseIds`) — один или несколько курсов Junior; они задаются при публикации и хранятся платформой, не в manifest; игра без курса видна только в общем каталоге и не попадает в рекомендации. Краткое описание, управление, ориентацию, поддерживаемые устройства и технические требования автор передаёт для проверки и информирования ученика.
4. Список библиотек с точными версиями, внешних сервисов и необходимых разрешений, если они используются.
5. Краткий отчёт о проверках и известных ограничениях.

Обложка относится к карточке каталога; она не должна быть скрытой зависимостью игрового runtime.

JSX содержит интерфейс, механику, тексты и переводы. JSON содержит данные, а не исполняемый код, строки функций или инструкции для `eval`. Единый формат математического банка не требуется. Правильные ответы разрешено хранить в JSX или JSON и проверять на клиенте: обязательной серверной проверки игровых решений нет.

JSX и JSON публикуются как единая неизменяемая версия. Автор не скачивает JSON самостоятельно: платформа разбирает его и передаёт через `content`. Если отдельного JSON нет, `content` равен `null`, а игра использует встроенные данные.

## 3. Формат JSX и зависимости

Начало файла:

```jsx
// @junior-gamecenter v1
import React, { useEffect, useRef, useState } from 'react';

export const gameCenterManifest = {
  // Метаданные из раздела 4.
};

export default function Game(props) {
  // Игровой компонент.
}
```

- `default` export — React function component. `gameCenterManifest` — именованный export с декларативными метаданными.
- React и ReactDOM предоставляет платформа. Не включайте второй React и не создавайте свой `createRoot`, HTML-документ или SSR entry point.
- Базовый импорт — только `react`. Используйте обычные hooks: `useState`, `useEffect`, `useRef`, `useMemo`, `useCallback`, `useReducer`, `useId`. Для немедленной бета-генерации действует единый профиль ниже; не выбирайте major React самостоятельно.
- Дополнительная библиотека, например Three.js, может быть заранее собрана внутрь одного JSX с сохранением лицензии. Не встраивайте вместе с ней React. Это не меняет основной формат поставки.
- Импорт другой библиотеки разрешается только после согласования её имени и версии с командой платформы. Произвольные npm-импорты, локальные файлы, CDN и dynamic import не входят в базовый контракт. Runtime не устанавливает зависимости из загруженного `package.json`.
- Для базовой автономной игры не нужны внешние запросы. Сервисы, API, дополнительные ресурсы и разрешения согласуются до генерации; их недоступность должна иметь понятное поведение. Это отдельные возможности конкретной игры, а не автоматическое разрешение на любой сетевой доступ.
- Backend LMS доступен игре только через callbacks. Не встраивайте адреса API, пароли, токены, ключи, прямой `fetch` результатов или работу с LMS storage.

React-модуль, manifest и встроенные зависимости должны корректно разбираться компилятором. Не удаляйте `import` и `export` регулярными выражениями при подготовке поставки.

### Единый профиль бета-генерации

- Проверяемая база: **React 18.3.1 и ReactDOM 18.3.1**, один общий экземпляр React; обычный JSX с classic transform. React 19 API и собственный React renderer не используются. Это профиль совместимости авторских бет, а не заявление о готовом production runtime или окончательный выбор способа изоляции.
- Формат: JavaScript/JSX ES module, без TypeScript-аннотаций в `Game.jsx`. Блоки `ts` в этом документе описывают типы, а не код для вставки в JSX. Hooks вызываются по правилам React, без условий и изменения их порядка.
- В базовом окружении доступны DOM, Canvas 2D, Pointer Events, ResizeObserver, requestAnimationFrame, Page Visibility API и Web Audio. UUID создаются через `crypto.randomUUID()`; запуск — по HTTPS или на localhost.
- Допустимые `requiredCapabilities` в базовой бете: `[]` либо `['webgl2']`. Имя capability не устанавливает библиотеку и не выдаёт разрешение. Другие capability-коды, внешние сервисы, камера/микрофон и host-зависимости требуют отдельного согласованного расширения до генерации.
- Three.js и подобные библиотеки разрешено включить внутрь файла без второго React, указав точную версию в `dependencies`. Для первой беты без согласованных расширений не используйте `delivery: 'host'`, внешние изображения, шрифты, CDN или запросы к сторонним API.
- Самостоятельный локальный просмотр выполняется отдельным тестовым хостом: он создаёт React root и передаёт props из раздела 5. Сам файл игры не превращается в HTML-приложение. Не помечайте имитацию сохранения в таком хосте как настоящую backend-проверку.

## 4. Manifest игры

Manifest — обычный объект с литералами, массивами и вложенными объектами. В нём нет функций, вызовов API, вычисления настроек из `window` и исполняемых выражений.

Все верхнеуровневые поля полного примера обязательны, включая пустые `levelIds`, `requiredCapabilities`, `dependencies`, `metrics` и `bestResult: null`, когда соответствующих возможностей нет. Вложенные `ageRange.max`, `metrics.<имя>.min/max/integer` необязательны. `gameId`, `modeIds`, `levelIds` и имена метрик — стабильные строковые ключи без точек; названия для ученика не используются как ID. Массивы ID не содержат дубликатов. `version` задаётся строкой вида `1.0.0`.

```js
export const gameCenterManifest = {
  contractVersion: 1,
  gameId: 'number-snake',
  version: '1.0.0',
  kind: 'endless',
  title: { uz: 'Sonli ilon', ru: 'Числовая змейка', en: 'Number Snake' },
  languages: ['uz', 'ru', 'en'],
  ageRange: { min: 7, max: 12 },
  orientation: 'any',
  devices: { mobile: true, desktop: true },
  modeIds: ['default'],
  levelIds: [],
  requiredCapabilities: [],
  dependencies: [],
  scoreVersion: 1,
  metrics: {
    score: { min: 0, integer: true },
    distance: { min: 0, integer: true }
  },
  bestResult: {
    outcomes: ['failure'],
    orderBy: [
      { field: 'metrics.score', direction: 'desc' },
      { field: 'metrics.distance', direction: 'desc' }
    ]
  }
};
```

| Поле | Правило |
| --- | --- |
| `contractVersion` | `1` |
| `gameId` | Постоянный уникальный идентификатор игры; после публикации не меняется |
| `version` | Версия поставки автора; сервер дополнительно создаёт собственный `revisionId` и checksum |
| `kind` | `level`, `endless`, `free` или `mixed` |
| `title`, `languages` | Название на UZ/RU/EN; все три языка обязательны |
| `ageRange` | Целый минимальный возраст; максимальный можно не задавать |
| `orientation` | `any`, `portrait` или `landscape` |
| `devices` | `mobile: true` обязательно; `desktop` описывает реальную поддержку |
| `modeIds` | Непустой массив стабильных ID режимов; для одного режима — `['default']` |
| `levelIds` | Стабильные уникальные ID уровней; `[]`, если уровней нет. Для нескольких режимов ID уровней уникальны в пределах всей игры |
| `requiredCapabilities` | Например `['webgl2']`; `[]`, если дополнительных возможностей нет. Разрешения вроде камеры требуют отдельного согласования |
| `dependencies` | `[]` либо записи `{ name, version, delivery }`, где `delivery` — `embedded` или предварительно согласованное `host` |
| `scoreVersion` | Положительная целая версия правил рекорда; при совместимых обновлениях сохраняется |
| `metrics` | Описание числовых показателей. Каждый показатель может задавать `min`, `max`, `integer`; универсальной шкалы нет |
| `bestResult` | Правило автора либо `null`, если в игре понятие рекорда отсутствует |

### Как автор задаёт лучший результат

Сравниваются результаты только одной игры, одного режима, одного уровня или области без уровней и одной `scoreVersion`. Произвольно сравнивать результаты разных игр нельзя.

`outcomes` — непустой массив допустимых исходов из `success`, `failure`, `finished`, `aborted`, выбранных автором. По умолчанию примеров `aborted` не участвует; автор может включить его, если достигнутый показатель имеет смысл при добровольном выходе и передаются все поля сравнения. Для змейки обычный проигрыш `failure` может дать лучший результат; для головоломки автор может учитывать только `success`.

`orderBy` — непустой массив, задающий лексикографическое сравнение: сначала первое поле, при равенстве второе и так далее. `desc` означает «больше — лучше», `asc` — «меньше — лучше». Допустимы `metrics.<имя объявленной метрики>` и `durationSeconds`. Все поля сравнения должны существовать и быть конечными числами в каждом подходящем для рекорда результате. При полном равенстве сохраняется прежний рекорд.

Если правила отличаются по режимам, `bestResult` имеет вид `{ byMode: { default: RULE, timed: RULE } }`, где каждое значение — объект с `outcomes` и `orderBy` либо `null`. Ключи совпадают с `modeIds`. Одновременное использование `byMode` и общего `orderBy` недопустимо.

История попыток сохраняется и при `bestResult: null`. Свободной игре не нужно придумывать бессодержательные очки ради общего формата.

## 5. Props от платформы

```jsx
<Game
  context={context}
  lang="uz"
  content={null}
  progress={progress}
  saveState={saveState}
  onAttemptStart={handleAttemptStart}
  onAttemptEnd={handleAttemptEnd}
  onRetrySave={handleRetrySave}
  onExit={handleExit}
  onEvent={handleOptionalEvent}
/>
```

| Prop | Содержание |
| --- | --- |
| `context` | `{ gameId, revisionId, sessionId, studentId, ageGroup, classLevel, environment }` |
| `lang` | `uz`, `ru` или `en`; для неизвестного значения локальный fallback — `uz` |
| `content` | Разобранный JSON либо `null`; структура определяется автором и проверяется игрой до начала попытки |
| `progress` | Серверный прогресс и сводные результаты из раздела 8 |
| `saveState` | Текущее состояние доставки операций из раздела 7 |
| `onAttemptStart(payload)` | Обязательный callback регистрации начала попытки |
| `onAttemptEnd(result)` | Обязательный callback передачи конечного результата |
| `onRetrySave(attemptId)` | Повтор доставки уже принятых операций с теми же данными |
| `onExit()` | Запрос выхода в каталог; не завершает игру победой |
| `onEvent(event)` | Необязательные некритичные события аналитики; не заменяют сохранение попыток |

`context.environment` — `play` или `preview`. В preview используются тестовый контекст и имитация сохранения без изменения данных учеников.

В `context` поля `gameId`, `revisionId` и `sessionId` — непустые строки. `studentId` — строка либо `null` в preview, `ageGroup` — строка либо `null`, `classLevel` — положительное целое либо `null`. Платформа передаёт полные пустые структуры `progress: { completedLevelIds: [], scopes: [] }` и `saveState: { attempts: {} }`, а не `undefined`, когда сохранений нет.

`studentId` — идентификатор, не токен. Имя, телефон, email и другие личные данные в игру не передаются. `ageGroup` и `classLevel` могут быть `null`. Игра не должна требовать их, если они не нужны механике. Сервер определяет владельца результатов по авторизованному запуску, а не по переданному из JSX Student ID.

`sessionId` создаёт платформа на открытие игры; `attemptId` создаёт игра на отдельное испытание. Новый запуск с другим учеником, игрой, revision или content требует remount. Обновление `progress`, `saveState`, языка и ссылок на callbacks само по себе не перезапускает партию. Читайте актуальные callbacks; не сохраняйте устаревшие замыкания навсегда.

Контекст и props доступны только для чтения. Не мутируйте объекты платформы.

Нормативные сигнатуры callbacks: `onAttemptStart(payload): void`, `onAttemptEnd(result): void`, `onRetrySave(attemptId): void`, `onExit(): void`, `onEvent(event): void`. Первые четыре обязательны. Это синхронная передача команды хосту, а не Promise API: не используйте `.then()`, `await` или возвращаемое значение для решения, можно ли играть или считать результат сохранённым. Совместимый хост не выбрасывает исключения из этих callbacks; ошибки валидации, локальной очереди и backend переводятся в `saveState`. Хост может обрабатывать команду асинхронно внутри себя, не меняя этой сигнатуры.

Если используется `onEvent`, передавайте `{ name, data }`: `name` — непустой машинный код события, `data` — необязательный объект с JSON-совместимыми значениями. Время приёма и контекст добавляет платформа. Проверяйте наличие callback перед вызовом; событие аналитики не должно блокировать игру и не заменяет `onAttemptStart` или `onAttemptEnd`.

## 6. Сессии, попытки и результаты

### Начало попытки

Простое открытие игры и чтение инструкции не являются попыткой. Автор выбирает понятную границу начала: «Начать партию», «Испытать мост», «Начать эксперимент».

```js
onAttemptStart({
  attemptId: crypto.randomUUID(),
  modeId: 'default',
  levelId: null,
  startedAt: new Date().toISOString()
});
```

- `attemptId` — новый UUID для каждой новой попытки. Храните его в состоянии или ref до конца попытки. Не создавайте ID в каждом render.
- `modeId` принадлежит `manifest.modeIds`.
- `levelId` — ID из `manifest.levelIds` либо `null`; для бесконечной игры уровни не требуются.
- Для `kind: 'level'` список уровней непустой и каждая попытка содержит ненулевой `levelId`. Для `endless` и `free` список уровней пустой, а поле передаётся явно как `levelId: null`. Для `mixed` его значение зависит от выбранного режима; поля не опускаются.
- На одном mount базового контракта одновременно активна одна попытка.
- Повтор доставки использует прежний ID. Новый реальный retry игры, replay или новая партия получает новый ID.
- Зарегистрированная попытка остаётся в истории независимо от её исхода.

### Конец попытки

```js
onAttemptEnd({
  attemptId: 'UUID той же попытки',
  outcome: 'failure',
  reason: 'collision',
  endedAt: new Date().toISOString(),
  durationSeconds: 42,
  metrics: { score: 240, distance: 80 },
  data: { collectedNumbers: 12 }
});
```

| Поле | Правило |
| --- | --- |
| `attemptId` | Совпадает с ранее зарегистрированной попыткой |
| `outcome` | `success`, `failure`, `finished` или `aborted` |
| `reason` | Необязательный машинный код причины; локализованный текст выводится самой игрой |
| `endedAt` | ISO timestamp; сервер дополнительно хранит собственное время получения |
| `durationSeconds` | Конечное неотрицательное число активных секунд; время паузы и скрытой вкладки не входит |
| `metrics` | Объект с объявленными в manifest конечными числовыми показателями; без `NaN` и `Infinity`. Для прерывания допустимы только уже известные показатели |
| `data` | Необязательный JSON-объект или `null`; массив, строку или другое скалярное значение поместите внутрь его поля, например `{ items: [...] }` |

`success` — испытание успешно выполнено. При ненулевом `levelId` платформа добавляет этот уровень в пройденные. `failure` — обычное игровое поражение. `finished` — нормальный конец без деления на победу и поражение. `aborted` — игрок прервал незавершённую попытку. Технический сбой не следует выдавать за игровое поражение или успешное прохождение.

Одна попытка имеет одно начало и не более одного конечного результата. Игра защищает завершение ref-флагом от повторного вызова из таймера, анимации, двойного клика или effect. При передаче результата формируется неизменяемый снимок, не ссылка на продолжающее меняться состояние.

При ошибке сохранения не создавайте новую попытку, не пересчитывайте результат и не меняйте timestamps. Для повтора используйте `onRetrySave(attemptId)`. Платформа обеспечивает идемпотентность начала и конца по отдельности; повторный конец с тем же ID и другими данными является конфликтом, а не новой попыткой.

**Запрещено:** отправлять результат на каждом кадре, начислять деньги или баллы LMS, объявлять игру пройденной после первого callback, считать закрытие вкладки доказательством успешного сохранения.

`metrics` содержит подмножество показателей, объявленных в manifest. Разные режимы могут использовать разные показатели: например, `distance` для раннера и `moves` для головоломки. Для исхода, участвующего в рекорде, обязательны все поля соответствующего правила `bestResult`; остальные обязательные показатели автор описывает для своего режима. Для свободной игры и прерывания допустим пустой объект `{}`. Не подставляйте фиктивные нули вместо показателей, которых в этом режиме нет.

`data` и `metrics` не содержат DOM, React elements, функций, циклических ссылок, Blob, секретов или персональных данных. Большие записи кадров и бинарные ресурсы не передаются как результат; специальные случаи согласуются отдельно. Платформа проверяет соответствие manifest, типы, объявленные диапазоны и привязку к запуску; это не означает повторного вычисления игровой правильности на сервере.

### Выход и принудительное закрытие

Если игрок нажал кнопку выхода внутри JSX при активной попытке, игра один раз отправляет `onAttemptEnd` с `outcome: 'aborted'` и текущими известными показателями, затем вызывает `onExit()`.

Если результат уже сформирован, выход не должен заменить его на `aborted`. Выход после поражения и новая партия не превращают проигранную попытку в успешную.

Платформа обрабатывает собственную навигацию отдельно. При выходе через внешнюю кнопку или закрытии приложения игра может не успеть прислать итог. Платформа сохраняет уже зарегистрированное начало и различает незакрытую/прерванную попытку и полноценный результат. Не выдумывайте финальные очки и точную длительность для такого случая. Гарантировать callback после аварийного закрытия браузера невозможно.

## 7. Статус сохранения и ошибки доставки

Callbacks `onAttemptStart` и `onAttemptEnd` передают команду хосту; их возвращаемое значение игра не использует как доказательство сохранения. Хост обновляет `saveState`. Это не требование реализовать HTTP или очередь внутри JSX.

```js
saveState = {
  attempts: {
    'attempt-uuid': {
      start: { status: 'saved', errorCode: null },
      end: { status: 'queued', errorCode: 'OFFLINE' }
    }
  }
};
```

Отсутствующая запись эквивалентна `idle`. Для каждой операции возможны состояния:

| `status` | Значение и поведение JSX |
| --- | --- |
| `idle` | Операция ещё не зарегистрирована; не показывать «Сохранено» |
| `saving` | Платформа обрабатывает команду или отправляет её; показать сохранение |
| `queued` | Команда надёжно записана в локальную очередь платформы, но сервер ещё не подтвердил запись; показать ожидание отправки |
| `saved` | Backend подтвердил сохранение; только теперь показать «Сохранено» |
| `error` | Операция не завершилась успешно; показать понятное сообщение и повтор через `onRetrySave` |

Статус `queued` не является обещанием серверного сохранения. Платформа не имеет права объявить команду `queued`, если запись в устойчивую локальную очередь не удалась. `saving` также не подтверждает устойчивую запись.

Операции `start` и `end` имеют независимые статусы. Показывайте ошибку `start` уже во время партии, а не только после результата; кнопка повтора вызывает `onRetrySave` с тем же `attemptId`. Если начало не сохранено, конец не может стать `saved`. При `start: error` и принятом конечном результате хост также помечает заблокированный `end` как `error` с `errorCode: 'START_NOT_SAVED'`. Повтор по ID заново доставляет нужные операции в порядке start → end без новых callbacks из игры и без изменения исходных данных. `errorCode` — `null` для состояний без ошибки либо строка машинного кода; игра должна иметь общий локализованный текст для неизвестного кода.

Платформа доставляет начало перед концом, повторяет временные сбои и не дублирует историю или рекорды. Игра может продолжать партию при временной потере связи; сетевой запрос не должен останавливать игровой цикл. Результаты предыдущих партий остаются доступными, даже если ученик начал новую попытку до завершения их отправки.

Новая партия не должна скрывать неподтверждённые результаты. Храните их снимки до подтверждения либо показывайте операции из `saveState` отдельным списком с повтором для каждого `attemptId`. Общую ошибку сохранения нельзя очищать только потому, что игрок нажал «Играть ещё».

При выходе платформа обеспечивает устойчивый приём уже переданных команд до удаления плеера и не требует ждать восстановления интернета. Если локально сохранить их невозможно, она сообщает о риске потери и оставляет возможность явного выхода без сохранения. Игра всегда имеет доступную кнопку выхода.

JSX локализует сообщения о сохранении, ожидании и ошибках. Машинный `errorCode` не выводится ребёнку вместо понятного текста. Критичные ошибки запуска, когда JSX вообще не отрисовался, показывает платформа.

## 8. Прогресс и повторные запуски

```js
progress = {
  completedLevelIds: ['bridge-01'],
  scopes: [
    {
      modeId: 'default',
      levelId: 'bridge-01',
      scoreVersion: 1,
      attemptsCount: 3,
      lastResult: null,
      bestResult: null
    }
  ]
};
```

`lastResult` и `bestResult` равны `null` либо имеют следующую точную структуру `StoredResult`:

```ts
type StoredResult = {
  attemptId: string;
  gameId: string;
  revisionId: string;
  sessionId: string;
  modeId: string;
  levelId: string | null;
  scoreVersion: number;
  startedAt: string;
  endedAt: string;
  receivedAt: string;
  outcome: 'success' | 'failure' | 'finished' | 'aborted';
  reason: string | null;
  durationSeconds: number;
  metrics: Record<string, number>;
  data: Record<string, unknown> | null;
};
```

Все поля `StoredResult` присутствуют; отсутствовавшие в исходном payload `reason` и `data` нормализованы в `null`. ID — строки; `scoreVersion` — положительное целое; timestamps — ISO строки. `data` содержит только JSON-совместимые значения. `receivedAt` — серверное время первого сохранения конечного результата. Остальной контекст добавляет платформа из зарегистрированного запуска и начала попытки. Автор не подставляет `revisionId` или владельца вручную в `onAttemptEnd`.

В первом запуске соответствующих записей области нет либо её результаты равны `null`. Для игр без уровней `completedLevelIds: []`, а у записи области `levelId: null`.

`attemptsCount` — количество уникальных зарегистрированных попыток в этой области. Полная история принадлежит backend; при каждом запуске не нужно загружать её целиком. `lastResult` — конечный результат наиболее поздно зарегистрированного начала попытки в этой области, включая поражение или прерывание. Backend один раз назначает порядок при первом сохранении начала, а повторная доставка его не меняет. Поздно доставленный конец старой попытки не заменяет результат более новой. Платформа сохраняет порядок команд одного запуска; порядок запусков с разных устройств определяется регистрацией на backend, а не часами клиента. `bestResult` выбирается по правилам автора. Незакрытое начало без результата учитывается в истории, но не становится рекордом и не скрывает последний известный конечный результат.

`progress.scopes` может содержать записи прежних `scoreVersion`: история не исчезает при обновлении. Текущий рекорд ищется по полному сочетанию modeId, levelId и действующей scoreVersion; нельзя брать первую запись только по modeId. `completedLevelIds` относится ко всей игре и не ограничивается версией правил рекорда.

`progress` содержит серверные данные. Только что достигнутый результат до подтверждения можно показывать локально с честным статусом сохранения. Не заменяйте им серверный рекорд без обозначения, что он ещё не сохранён.

Повторный запуск должен отображать уже сохранённые результаты и пройденные уровни. Обновление props прогресса во время партии не сбрасывает текущую игру, не телепортирует игрока и не запускает новую попытку.

**Сохранённый прогресс не равен checkpoint.** Не нужно восстанавливать координаты змейки, недостроенный мост или точную позицию персонажа. Восстановление незаконченной партии опционально и требует отдельно согласованного расширения для записи/чтения состояния. Не придумывайте для него неподдерживаемые callbacks в базовом v1.

### 8.1 Карточка каталога GameLab: статусы, прогресс, рекомендации (уровень платформы)

Этот раздел описывает поведение каталога, а не JSX. Статусы карточки платформа вычисляет сама по `progress` и manifest; игра их не передаёт и не получает.

| Статус | Подпись на карточке | Когда присваивается |
| --- | --- | --- |
| `new` | «Yangi» | `attemptsCount = 0` во всех областях игры |
| `in_progress` | «Davom etmoqda» | `kind` равен `level` или `mixed`, есть хотя бы одна попытка, `completedLevelIds` не покрывает все `levelIds` |
| `played` | «O‘ynalgan» | `kind` равен `endless` или `free`, есть попытки; завершённость не определена, на карточке показывается рекорд или число попыток |
| `completed` | «Bajarilgan» | `kind` равен `level`, все `levelIds` пройдены; повторное прохождение разрешено |
| `locked` | «Bloklangan» | Решение платформы: предыдущая игра, возраст, maintenance; причина показывается ученику. Не часть manifest и JSX |

- **Прогресс на карточке.** Для игр с уровнями — `completedLevelIds.length / levelIds.length`, показывается как число уровней, а не как процент. Для `endless` и `free` — рекорд (значение первого поля `bestResult.orderBy`) либо число попыток, если рекорда нет.
- **Раздел «Davom ettirish».** Содержит игры в статусах `in_progress` и `played`. Кнопка открывает игру, но **не восстанавливает позицию внутри партии**: checkpoint в базовом v1 не поддерживается (раздел 8).
- **Раздел «Siz uchun tavsiya etiladi».** Платформа выбирает игры, у которых `courseIds` пересекаются с курсами, на которые записан ученик, в статусе `new` и не показанные в «Davom ettirish». Редакторские флаги (`isRecommended`, `isPopular`) относятся к платформе.
- **Класс на карточке.** Каждая карточка (в «Davom ettirish», «Siz uchun tavsiya etiladi» и «Barcha o‘yinlar») рядом с курсом показывает рекомендуемый класс: диапазон «3–4-sinf» или одно значение «2-sinf». Это метаданные платформы (`gradeFrom`, `gradeTo`, целые 1–11, `gradeFrom ≤ gradeTo`), задаются при публикации. Поле `ageRange` manifest остаётся техническим минимумом и на карточке не показывается. Класс — подсказка, а не ограничение: игра для другого класса не блокируется.
- **Фильтры.** Глобальный чип курса фильтрует все разделы. Поиск и дополнительные фильтры каталога (курс, статус, сложность, класс, «только рекомендованные») влияют только на раздел «Barcha o‘yinlar». Фильтр по классу `N` оставляет игры, у которых `gradeFrom ≤ N ≤ gradeTo`.
- **Награды.** Карточки никогда не показывают монеты и награды.

Данные о блокировке, рекомендациях и курсах — метаданные платформы; их нельзя запрашивать у JSX и нельзя ожидать от игры.

## 9. Обновления и сохранение пройденного

- `gameId`, существующие `modeIds` и `levelIds` — постоянные идентификаторы, а не номера элементов массива или отображаемые названия.
- **Пройденный уровень остаётся пройденным после обновления, даже если автор изменил его задание или оформление.** Существующий ID сохраняет статус. Новому отдельному уровню нужен новый ID.
- Нельзя переименовать все ID при очередной генерации и тем самым скрыто сбросить прогресс. Удалённые уровни и их результаты остаются в истории, даже если больше не показываются в актуальном списке.
- Смена JSX или JSON не удаляет историю попыток и результатов.
- При совместимом обновлении правило рекорда и `scoreVersion` сохраняются. Значение уже опубликованной `scoreVersion` навсегда закрепляет смысл метрик, единицы и правила сравнения. При несовместимом изменении автор выбирает число больше максимального за всю историю игры, включая откаты; нельзя повторно занять номер другими правилами. Новые рекорды считаются отдельно, старые остаются доступны в истории. Это не сбрасывает статус пройденных уровней.
- Новая публикация применяется к новым запускам. Уже открытая игра продолжает работать на закреплённом `revisionId`; её результаты принимаются по правилам именно этой версии.
- Откат публикации не означает откат данных ученика.
- Maintenance или скрытие запрещают новые запуски. Уже открытые игры не останавливаются принудительно, их результаты продолжают сохраняться.

Универсальный инструмент миграции и сброса прогресса не является требованием первой версии. Нельзя добавлять автоматический сброс ради упрощения обновлений.

## 10. Интерфейс и жизненный цикл

### Оформление и изоляция

Игра оформляется автором свободно. Используйте собственный корневой элемент и уникальный префикс классов, например `gc-number-snake`. CSS можно включать через `<style>` в JSX, ограничив селекторы корнем игры.

Не меняйте глобальные `html`, `body`, `#root`, чужие кнопки и стили LMS. Не ищите DOM родительской страницы, не читайте её storage и не рассчитывайте на глобальные переменные хоста. Не обращайтесь к `window.parent` и не реализуйте собственный `postMessage` транспорт: интеграцию обеспечивает платформа.

Этот контракт не обязывает автора использовать iframe и не требует от него HTML-файл. Способ изоляции выбирается платформой; компонент должен работать внутри выделенного ему контейнера независимо от этого решения.

Контейнер игры получает доступную ширину и высоту. Корень занимает `width: 100%; height: 100%; min-height: 0`. Измеряйте фактический контейнер, например через ref и `ResizeObserver`, а не размеры всего окна LMS. Не создавайте горизонтальную прокрутку. На маленьких экранах инструкция и результат могут прокручиваться, если иначе текст нельзя прочитать.

### Управление и мобильные устройства

- Все основные действия доступны касанием; нет обязательного hover, правой кнопки мыши или только клавиатурного действия.
- Для перетаскивания поддерживайте Pointer Events и корректное завершение/отмену жеста. `touch-action: none` ограничивайте игровой областью, где это необходимо; не блокируйте всю страницу.
- Если заявлена поддержка ПК, обеспечьте подходящие мышь/клавиатуру и видимый фокус.
- При смене размеров или ориентации состояние не должно пропадать. Если нужна конкретная ориентация, покажите локализованную просьбу повернуть устройство и приостановите игру.
- Звук включается после действия пользователя и может быть отключён. Отказ или ошибка аудио не мешают игре.
- При скрытии вкладки или уходе приложения в фон приостанавливайте игровой цикл и активный таймер. Возврат не должен мгновенно приводить к проигрышу из-за накопленного времени.
- При отсутствии WebGL или другой обязательной возможности покажите понятное сообщение. Невозможность запуска не считается успехом или игровым поражением.

### Очистка

При unmount отменяйте `requestAnimationFrame`, таймеры, подписки, observers и глобальные обработчики; освобождайте аудио и WebGL-ресурсы. Не выполняйте сохранение результата как побочный эффект cleanup: React может вызывать cleanup при проверках жизненного цикла, а не только при реальном выходе.

Локальное состояние и refs допустимы. Они не заменяют серверное сохранение. Не используйте `localStorage` игры как источник истины о результатах ученика.

## 11. Пример минимального компонента

Это проверяемый пример жизненного цикла бесконечной игры, а не готовая образовательная механика. Кнопка очков обозначает игровой ввод, столкновение — обычное поражение. В настоящей игре замените эти действия механикой, полноценным полем и инструкцией. Пример регистрирует реальные интервалы активного времени, исключает скрытую вкладку, показывает обе операции сохранения и сохраняет доступ к ошибкам предыдущих партий. Симуляции движения в нём нет.

```jsx
// @junior-gamecenter v1
import React, { useEffect, useRef, useState } from 'react';

export const gameCenterManifest = {
  contractVersion: 1,
  gameId: 'gamecenter-contract-example',
  version: '1.0.0',
  kind: 'endless',
  title: { uz: 'Namuna', ru: 'Пример', en: 'Example' },
  languages: ['uz', 'ru', 'en'],
  ageRange: { min: 7 },
  orientation: 'any',
  devices: { mobile: true, desktop: true },
  modeIds: ['default'],
  levelIds: [],
  requiredCapabilities: [],
  dependencies: [],
  scoreVersion: 1,
  metrics: { score: { min: 0, integer: true } },
  bestResult: {
    outcomes: ['failure'],
    orderBy: [{ field: 'metrics.score', direction: 'desc' }]
  }
};

const texts = {
  uz: {
    title: 'Kontrakt namunasi', intro: 'Boshlang, ochko to‘plang va partiyani tugating.',
    start: 'Boshlash', point: 'Ochko qo‘shish', lose: 'To‘qnashuv', again: 'Yana o‘ynash',
    exit: 'Chiqish', score: 'Ochko', best: 'Rekord', round: 'Partiya',
    begin: 'Boshlanish', resultLabel: 'Natija', idle: 'Hali saqlanmagan',
    saving: 'Saqlanmoqda…', queued: 'Yuborish kutilmoqda', saved: 'Saqlandi',
    error: 'Saqlanmadi', retry: 'Qayta yuborish'
  },
  ru: {
    title: 'Пример контракта', intro: 'Начните, наберите очки и завершите партию.',
    start: 'Начать', point: 'Добавить очко', lose: 'Столкновение', again: 'Играть ещё',
    exit: 'Выйти', score: 'Очки', best: 'Рекорд', round: 'Партия',
    begin: 'Начало', resultLabel: 'Результат', idle: 'Ещё не сохранено',
    saving: 'Сохранение…', queued: 'Ожидает отправки', saved: 'Сохранено',
    error: 'Не сохранено', retry: 'Повторить отправку'
  },
  en: {
    title: 'Contract example', intro: 'Start, collect points and end the round.',
    start: 'Start', point: 'Add a point', lose: 'Collision', again: 'Play again',
    exit: 'Exit', score: 'Score', best: 'Best', round: 'Round',
    begin: 'Start registration', resultLabel: 'Result', idle: 'Not saved yet',
    saving: 'Saving…', queued: 'Waiting to send', saved: 'Saved',
    error: 'Not saved', retry: 'Retry saving'
  }
};

export default function Game({
  lang = 'uz', progress, saveState,
  onAttemptStart, onAttemptEnd, onRetrySave, onExit
}) {
  const t = texts[lang] || texts.uz;
  const run = useRef(null);
  const [phase, setPhase] = useState('intro');
  const [score, setScore] = useState(0);
  const [attempts, setAttempts] = useState([]);
  const [visible, setVisible] = useState(true);
  const best = progress.scopes.find(s =>
    s.modeId === 'default' && s.levelId === null &&
    s.scoreVersion === gameCenterManifest.scoreVersion
  )?.bestResult?.metrics?.score;

  useEffect(() => {
    function visibilityChanged() {
      const current = run.current;
      const now = performance.now();
      if (current && !current.ended) {
        if (current.runningSince !== null) {
          current.activeMs += now - current.runningSince;
        }
        current.runningSince = document.hidden ? null : now;
      }
      setVisible(!document.hidden);
    }
    visibilityChanged();
    document.addEventListener('visibilitychange', visibilityChanged);
    return () => {
      document.removeEventListener('visibilitychange', visibilityChanged);
      const current = run.current;
      if (current && !current.ended && current.runningSince !== null) {
        current.activeMs += performance.now() - current.runningSince;
        current.runningSince = null;
      }
    };
  }, []);

  function start() {
    if (document.hidden) return;
    if (run.current && !run.current.ended) return;
    const next = {
      attemptId: crypto.randomUUID(), score: 0, ended: false,
      activeMs: 0, runningSince: performance.now()
    };
    run.current = next;
    setAttempts(previous => [...previous, { attemptId: next.attemptId, result: null }]);
    setScore(0);
    setPhase('playing');
    onAttemptStart({
      attemptId: next.attemptId, modeId: 'default', levelId: null,
      startedAt: new Date().toISOString()
    });
  }

  function addPoint() {
    const current = run.current;
    if (!current || current.ended || document.hidden) return;
    current.score += 1;
    setScore(current.score);
  }

  function end(outcome) {
    const current = run.current;
    if (!current || current.ended) return;
    if (current.runningSince !== null) {
      current.activeMs += performance.now() - current.runningSince;
      current.runningSince = null;
    }
    current.ended = true;
    const snapshot = {
      attemptId: current.attemptId, outcome,
      reason: outcome === 'aborted' ? 'player_exit' : 'collision',
      endedAt: new Date().toISOString(),
      durationSeconds: Number((current.activeMs / 1000).toFixed(3)),
      metrics: { score: current.score }
    };
    setAttempts(previous => previous.map(attempt =>
      attempt.attemptId === snapshot.attemptId ? { ...attempt, result: snapshot } : attempt
    ));
    setPhase('result');
    onAttemptEnd(snapshot);
  }

  return <main className="gc-contract-example" lang={texts[lang] ? lang : 'uz'}>
    <style>{`
      .gc-contract-example{box-sizing:border-box;width:100%;height:100%;min-height:0;
        overflow:auto;padding:20px;font-family:system-ui;background:#f5f7fb;color:#17243a}
      .gc-contract-example button{min-height:44px;padding:10px 16px;margin:4px;
        font:inherit;cursor:pointer}
      .gc-contract-example button:focus-visible{outline:3px solid #315ce8}
    `}</style>
    <h1>{t.title}</h1>
    <p>{t.intro}</p>
    <p>{t.score}: {score}</p>
    <p>{t.best}: {best ?? '—'}</p>
    {phase !== 'playing' && <button disabled={!visible} onClick={start}>
      {phase === 'intro' ? t.start : t.again}
    </button>}
    {phase === 'playing' && <>
      <button disabled={!visible} onClick={addPoint}>{t.point}</button>
      <button disabled={!visible} onClick={() => end('failure')}>{t.lose}</button>
    </>}
    {attempts.map((attempt, index) => {
      const operations = saveState.attempts[attempt.attemptId];
      const startStatus = operations?.start?.status || 'idle';
      const endStatus = startStatus === 'error'
        ? 'error' : (operations?.end?.status || 'idle');
      const retryAvailable = startStatus === 'error' ||
        (attempt.result && endStatus === 'error');
      return <section key={attempt.attemptId} aria-live="polite">
        <p>{t.round} {index + 1}</p>
        <p>{t.begin}: {t[startStatus]}</p>
        {attempt.result && <p>{t.resultLabel}: {attempt.result.metrics.score} — {t[endStatus]}</p>}
        {retryAvailable && <button
          onClick={() => onRetrySave(attempt.attemptId)}>{t.retry}</button>}
      </section>;
    })}
    <button onClick={() => { try { end('aborted'); } finally { onExit(); } }}>{t.exit}</button>
  </main>;
}
```

В настоящей игре тот же учёт времени должен учитывать ещё и её собственную паузу. В примере рекордом является только подтверждённый `progress`; локальные очки не выдаются за сохранённый рекорд. `try/finally` при выходе — дополнительная защита от неисправного тестового хоста; совместимый runtime всё равно обязан соблюдать не бросающие callbacks.

## 13. Проверки беты и приёмка интеграции

### Авторская бета с тестовым хостом

До реализации GameLab автор проверяет свою игру в отдельном хосте, который передаёт точные props и имитирует callbacks. Такой хост помечается как preview/mock и не начисляет награды, не пишет реальные результаты учеников и не называется production-интеграцией.

Минимальные сценарии имитации: пустые progress/saveState; start.error во время партии; start.saved + end.saving/queued/saved/error; end, заблокированный start.error; новая партия до сохранения старой; повтор по прежнему attemptId; повторный mount с заранее заданным progress; обновление языка, progress и saveState без remount. Сигнатуры callbacks и данные совпадают с этим контрактом; для имитации не добавляются новые props в авторскую игру.

- [ ] Файл компилируется, default component и manifest доступны; дополнительных несогласованных файлов и импортов нет.
- [ ] Первый запуск без прогресса и без JSON работает, если JSON не заявлен обязательным для этой игры. Повреждённый или неподходящий content даёт понятную ошибку до начала попытки.
- [ ] Инструкции, управление, ошибки и статусы доступны на UZ/RU/EN.
- [ ] Игра работает на заявленных смартфонах и планшетах; при заявленной поддержке ПК проверены мышь/клавиатура. Эмуляция viewport не заменяет проверку на реальном устройстве.
- [ ] Основная механика проходима или играбельна; touch, смена размеров/ориентации и работа без звука проверены.
- [ ] Начало, успех, поражение, повтор и выход дают правильные попытки. Для бесконечной игры смерть сохраняет результат и не превращается в ошибку запуска.
- [ ] Двойной клик, повторный кадр и повторная доставка не создают дубликаты. Быстрый повтор партии не теряет предыдущий результат.
- [ ] saving, queued, saved и error визуально различимы для start и end. Проверены имитация отсутствия связи, повтор по прежнему ID, старая ошибка после новой партии и выход с ожидающим сохранением.
- [ ] При повторном mount с заданным progress видны прежние результаты, рекорды и пройденные уровни. Изменение этих props и языка не сбрасывает партию.
- [ ] Новая версия JSX отображает переданный пройденный уровень с прежним ID как пройденный, даже если задание изменилось. Разные scoreVersion не смешиваются.
- [ ] Пауза и скрытие вкладки не ломают игру; unmount освобождает ресурсы и не отправляет ложный результат.
- [ ] Отсутствие обязательной возможности устройства не создаёт успешное прохождение или фиктивный проигрыш.
- [ ] Автор передал права на используемые материалы, зависимости с версиями и краткий отчёт с реальными результатами проверок и ограничениями.

Автор может передавать бету после этих проверок, явно указав, что сохранение и прогресс проверены с имитацией. Наличие непроверенного ещё production backend не является дефектом авторской механики.

### Приёмка платформы после подключения GameLab

Эти проверки выполняет команда платформы совместно с QA и автором до публикации, а не генератор вместо отсутствующего backend:

- [ ] Реальный авторизованный запуск связывает попытки с нужными учеником, игрой и revision.
- [ ] Сохранённые результаты и прогресс действительно читаются после нового входа; last/best, число попыток и пройденные уровни соответствуют истории.
- [ ] Подтверждены устойчивость локальной очереди, восстановление после reload, доставка start → end и отсутствие дубликатов при повторе. Одна лишь имитация статуса queued этого не доказывает.
- [ ] Отложенный конец старой попытки не заменяет lastResult более новой; повтор одного payload не меняет порядок.
- [ ] Публикация, rollback и изменение правил рекордов сохраняют историю и статус пройденного. Ранее занятая scoreVersion не получает другие правила после отката.
- [ ] Maintenance запрещает новые запуски, не останавливая текущие и сохранение их результатов.
- [ ] Preview и реальный плеер соблюдают одинаковые авторские props, профиль зависимостей и границы доступа; PM/PO подтвердил публикацию после продуктовой и технической проверки.

## 14. Применение к BridgeMaster

BridgeMaster — первая уровневая игра, а не универсальная модель всех игр GameLab. Его текущий callback `onFinished` сообщает только об успешном уровне и не является заменой общего `onAttemptEnd`.

Для соответствия этому контракту автор или адаптер должны:

- добавить manifest GameLab и регистрацию начала каждого испытания моста;
- передавать новый attemptId на каждое испытание, включая Retry внутри одной sessionId;
- передавать успех, поражение и прерывание; существующего failure event без полноценного результата недостаточно;
- принимать сохранённые пройденные уровни и результаты через progress;
- встроить переводы UZ/RU/EN, включая ошибки;
- отображать статус сохранения из saveState;
- ограничить глобальные CSS-селекторы собственным корнем и выполнить требования жизненного цикла;
- согласовать и проверить React runtime, сохранив встроенный Three.js и лицензию.

Восстановление недостроенного моста не требуется. Для бесконечной игры те же callbacks передают `levelId: null`, manifest содержит `levelIds: []`, а progress — `completedLevelIds: []`. Эти поля не опускаются: уровни необязательны, но форма контракта остаётся одинаковой.

## Приложение B. Справочный HTML `GameLab.html`

Файл `GameLab.html` — автономный справочный пример без сервера и внешних запросов.

**Что он показывает:**

- раскладка каталога и глобальные чипы курсов;
- состояния карточек и вывод статусов из раздела 8.1;
- диалог сведений об игре с уровнями;
- экраны внутри игры в стиле B;
- жизненный цикл попытки с имитацией `saveState`, включая ошибки start/end, повтор, `queued` и `saved`;
- отсутствие монет и наград.
- одна попытка — один проход экранов игры: выход до конца даёт `aborted`, завершение — `success` (игры с уровнями) или `finished` (игры без уровней); новая партия — новый `attemptId`;
- два вида карточек: игра с уровнями (в демо — три уровня) и игра без уровней со статусом `played` и рекордом;
- рекомендации по курсам ученика (в демо — Matematika и Dasturlash) и раздел «Davom ettirish» без восстановления позиции;
- переключатель режима сохранения в меню прототипа («Saqlash: normal / internet yo‘q / server xatosi»).

**Чем он не является:**

- это не JSX-игра и не runtime;
- хост в нём — имитация (mock);
- у демо-игр с уровнями все три уровня открывают один и тот же 15-экранный учебный пример; queued-операции в имитации не переживают перезагрузку страницы (у реальной платформы очередь устойчива);
- демонстрационный учебный контент написан только на узбекском, тогда как реальные игры обязаны поддерживать UZ/RU/EN;
- восстановления позиции (checkpoint) нет;
- все данные — образцы.
